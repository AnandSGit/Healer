Flow Orchestrator

The /healer:flow command chains multiple sub-commands into a pipeline. Use built-in presets, inline syntax, or custom YAML recipes.

# Built-in presets
/healer:flow feature          # brainstorm ?→ plan ?→ implement → test !→ review ?→ ship !→
/healer:flow fix              # diagnose → debug → fix → test !→ push ?→

# Inline custom chains
/healer:flow diagnose → fix → test !→ push
/healer:flow brainstorm ?→ plan ?→ implement → test !→ ship !→

# Custom recipes
/healer:flow pre-release      # from ~/.healer/recipes.yaml
/healer:flow hotfix

Gate Operators

OperatorNameOn SuccessOn Failure
→AUTOContinue automaticallyLog warning, continue anyway
?→INTERACTIVEPause: "Continue to {next}? [Y/n]"Pause: "Step failed. Continue? [Y/n/abort]"
!→MUST-PASSContinue automaticallyHALT flow. Suggest /healer:fix

Custom Recipes

Define your own flows in ~/.healer/recipes.yaml:

flows:
  my-workflow:
    description: "My custom pipeline"
    steps:
      - command: diagnose
        gate: must-pass        # !→
      - command: fix
        args: "unit"
        gate: auto             # →
      - command: review
        gate: interactive      # ?→
      - command: push
        gate: interactive      # ?→

Then run: /healer:flow my-workflow
